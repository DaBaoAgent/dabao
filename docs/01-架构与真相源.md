## 为什么项目根不复制技能代码

- Hermes 只从 `HERMES_HOME\skills\<name>\SKILL.md` 加载技能，cron 只从 `HERMES_HOME\scripts\` 执行脚本（调度器有路径穿越校验）。
- 复制一份到 `D:\@kaifa\dabao` 会造成**双真相源**：cron 读 A、人改 B，坑位库越走越偏。2026-10/11 `D:\@kaifa\dabao文案库` 被删而技能里没有备份，就是「有多个副本 = 哪个都不是真相源」的教训。
- 因此：
  - `skill\` = Windows **junction** → `HERMES_HOME\skills\dabao`（读写都落到同一份文件）
  - `tools\*.py` = 3 行薄壳 → `HERMES_HOME\scripts\<real>.py`
  - `cron\` = **只读快照**（jobs.snapshot.json + prompt 全文），改动一律改 jobs.json / `hermes cron edit`

## 目录职责表

| 路径 | 类型 | 可否手改 | 说明 |
|---|---|---|---|
| `skill\SKILL.md` | junction 实体 | ✅（改的是真相源） | 流程与坑位库，10 万字符上限，逐班日志写 references/ |
| `tools\*.py` | 薄壳 | ⚠️ 别改逻辑 | 只做转发；逻辑改 `HERMES_HOME\scripts` 原件 |
| `cron\*.json/md` | 快照 | ❌ | 由 `scripts\status.py --refresh-cron` 覆盖 |
| `mcp\upload-post\server.json` | 声明 | ✅ | 与 config.yaml 保持一致，服务地址/授权方式变才改 |
| `scripts\status.py` | 体检 | ✅ | 本项目自有代码，可扩展 |
| `state\` | 运行时 | ❌ | 不入库 |

## 数据流（一条片）

1. cron 05/19 点触发发布班 → 扫描素材库第一个未发目录；
2. staging 上传（create → PUT → complete，拿 `media_url`，6h 有效）；
3. 按平台分组调 `upload_video`（IG / X / FB / TG 各自版本）；
4. `get_status` 轮询 + 外部回读核验；
5. 全绿 → 目录加 `【已发】` + 写 `已发记录.md` → 移入 `@已发\`；
6. 有失败 → 留原地 + watchdog 30 分钟后补发一次。
